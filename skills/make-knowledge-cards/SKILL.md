# 知识卡片制作（make-knowledge-cards）

## Overview

本技能把一段文本（用户直接粘贴的文章，或本地 `.md` / `.txt` 文件）提炼成一组**知识卡片**。每张卡片只讲一个独立的知识点，包含四要素：标题、核心知识、简明解释、例子或自测问题。目标数量 5-8 张；当原文信息不足时，宁少勿凑。

适用场景举例：
- "把这篇关于量子纠缠的文章做成知识卡片"
- "读取 notes/xxx.md，提炼成复习卡片"
- "这段文字太长了，帮我把重点做成 6 张卡片"

不适用（直接说明不支持，不要强行处理）：
- 网页 / URL 抓取
- PDF 文件
- 导出为 Anki（.apkg / .csv 导入格式）
- 任何图形界面 / GUI 交互

## 输入处理

1. 判断输入类型：
   - 若用户在对话中**直接粘贴了文本**，直接以该文本为原文。
   - 若用户给的是**本地文件路径**（以 `.md` 或 `.txt` 结尾），用 Read 工具读取其内容作为原文。
   - 若既无粘贴文本也无有效文件，先请用户提供原文或文件路径，再继续。
2. 语言：**默认与原文保持一致**（中文原文→中文卡片，英文原文→英文卡片），除非用户另有要求。

## 提炼流程

按以下顺序处理，确保质量优先于数量：

1. **识别知识点**：通读原文，标出真正值得记住的内容——定义、原理、因果、方法、关键事实、易混淆点、结论。忽略开场白、过渡句、重复强调和纯修饰性内容；排除纯营销 / 宣传性、主观夸赞类陈述（如"好用""很快""很多人喜欢"），除非其中包含可验证的客观事实。
2. **去重合并**：同一概念在文中多处出现，合并为一张卡片；不要因为出现次数多就拆成多张。
3. **判定数量**：
   - 若独立知识点 ≥ 5，选取最重要的 5-8 个，产出 5-8 张。
   - 若独立知识点为 1-4 个，**如实产出对应数量的卡片**，并在卡片前用一行说明："原文可提炼的知识点较少（共 N 个），已如实产出，未强行凑数。"
   - 若独立知识点为 0 个（如纯营销文案、无实质信息的短文），**不产出任何卡片**，改而用一行说明："原文未提炼出可记忆的知识点，未强行产出卡片。"
   - 不要为了凑够 5 张而编造或拆分微小差异的内容。
4. **逐张填充四要素**（见下）。每张卡片必须是一个**独立、可单独理解**的知识点；不要出现"见上一张""接前文"之类的依赖。

## 卡片四要素

每张卡片严格包含以下四部分，顺序一致：

- **标题**：一句点明本卡片主题的短语（不是整段总结）。
- **核心知识**：一句话精准陈述该知识点（结论式，可独立成立）。
- **简明解释**：用 2-4 句用自己的话把核心知识讲清楚，语言通俗，避免照抄原文长句。
- **例子 / 自测**：二选一或两者都给（短则皆可）：
  - 例子：来自原文或可由原文直接推导的具象说明（**不得编造原文没有的事实、数据、人物、事件**）。
  - 自测问题：一个能用本卡片内容回答的思考题。

## 硬性约束（必须遵守）

- **不编造**：所有事实、数据、例子都必须能在原文中找到依据或由其直接推导。拿不准的内容宁可省略，也不要"补全"。
- **不重复**：卡片之间不重复同一知识点。
- **不凑数**：信息不足时不强行产出 5 张（见"判定数量"）。
- **不越界**：不抓取网页、不解析 PDF、不导出 Anki、不启动 GUI。遇到这些请求时直接说明本技能不支持，并给出替代建议（如：先把内容复制为文本再粘贴过来）。

## 输出格式

1. 在对话中按以下模板依次展示每张卡片：

```
## 卡片 N：<标题>

**核心知识：** <一句话>

**简明解释：** <2-4 句>

**例子 / 自测：** <例子或自测问题>
```

2. 同时把全部卡片写入当前工作目录下的 `knowledge-cards.md`（已存在则覆盖），方便用户保存与复用。文件结构与对话展示一致，并在开头注明生成时间与原文来源（"粘贴文本"或文件路径）。

## 自检清单

产出前快速核对：
- [ ] 每张卡片四要素齐全？
- [ ] 每张卡片只讲一个知识点？
- [ ] 没有重复知识点？
- [ ] 没有任何原文没有的事实/数据？
- [ ] 数量是否合理（不足 5 张时是否已说明原因）？
- [ ] 是否误用了网页/PDF/Anki/GUI 等不支持的功能？
